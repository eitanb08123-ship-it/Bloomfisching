# WhatsApp Gemini Bot

A WhatsApp auto-reply bot that uses the [Gemini API](https://ai.google.dev/) to generate real,
context-aware replies — no keyword matching, no canned responses. It connects to WhatsApp Web via
[`whatsapp-web.js`](https://wwebjs.dev/), keeps a short rolling conversation history per contact, and
sends that history to Gemini so replies stay coherent across a conversation.

## Features

- Context-aware replies generated by Gemini for every incoming text message
- Rolling per-contact conversation history (last `MAX_HISTORY_MESSAGES` messages), persisted to a local
  JSON file so it survives restarts
- **Local setup UI** — enter your Gemini API key through a form in your browser instead of hand-editing
  `.env`, with inline validation that catches an obviously-wrong key before it's saved
- Global pause (`/pauseall`, `/resumeall`, owner-only) and per-contact pause (`/pause`, `/resume`)
- Retries with exponential backoff on rate limits / transient API or network errors, with a graceful
  fallback message if Gemini is unreachable
- Automatic reconnect (with backoff) if the WhatsApp Web session drops
- Debounced, randomized "typing" delay before sending, so replies don't feel instant, plus a
  concurrency cap on simultaneous Gemini calls

## Project layout

```
whatsapp-claude-bot/
├── index.js          # entry point: checks setup status, then hands off to bot.js
├── bot.js            # WhatsApp client, Gemini calls, history, throttling
├── setup-server.js   # local-only HTTP server + HTML form that writes .env
├── setup.js          # `npm run setup` — reopen the setup UI on demand
├── config.js         # env var loading + defaults + the bot's persona/system prompt
├── .env.example      # template .env is created from on first run
└── package.json
```

## Requirements

- Node.js 20+
- A phone with WhatsApp installed (used once to scan the QR code)
- A [Gemini API key](https://aistudio.google.com/apikey) (Google AI Studio has a free tier — no credit
  card required to get started)

## Setup

1. Install dependencies:

   ```bash
   cd whatsapp-claude-bot
   npm install
   ```

2. Start the bot:

   ```bash
   npm start
   ```

   The first time you run this without a valid `GEMINI_API_KEY`, a **local setup UI** opens
   automatically instead of the bot — see below. Once it's saved, the bot starts right away in the
   same run.

### First-time setup (the local setup UI)

If `.env` is missing, or `GEMINI_API_KEY` in it is empty, `npm start` prints something like:

```
Setup required: open http://localhost:3000 in your browser to enter your Gemini API key.
```

1. Open that URL in your browser.
2. Go to https://aistudio.google.com/apikey, open your key's details, and click **Copy key** (don't
   select the text by hand — that can miss a character at either end).
3. Paste it into the form and click **Save**.
4. The form does a basic sanity check (length/characters) and rejects an obviously empty or malformed
   paste with an inline error, but it doesn't assume a specific prefix — Google has shipped more than
   one key format over time.
4. On success, the page confirms it saved, the local server shuts down, and the bot starts
   automatically in the same terminal — no need to run `npm start` again.

**How it works, and what it does/doesn't do:**

- Values are written **only** to your local `.env` file (created from `.env.example` if it doesn't
  exist yet, or updated in place if it does). They are never sent anywhere else, never echoed back to
  the browser after saving, and never printed to the console/logs.
- The server binds only to `127.0.0.1` (localhost) — it is never reachable from other devices on your
  network.
- Re-opening the form later shows a masked placeholder (`••••••••`) for any key that's already set, not
  the real value. Leaving a field blank and saving keeps the existing value untouched.
- `.env` stays listed in `.gitignore` — it's never meant to be committed either way.

This project only needs the Gemini API key — it doesn't use the official WhatsApp Business API (which
would need its own access token), because it logs in via a scanned WhatsApp Web QR code instead (see
below).

**To update the key later** (e.g. you rotated it), reopen the setup UI without starting the bot:

```bash
npm run setup
```

This opens the same form; when you save, it prints a reminder to run `npm start` and exits.

**Prefer editing `.env` by hand instead?** That still works — `cp .env.example .env`, fill in the value,
save. `npm start` will detect the key is already valid and skip the setup UI entirely. Either path is
fine; the setup UI just avoids the most common way to get the file wrong. Never commit your real `.env`
file or hardcode the API key in source either way.

## Logging in with WhatsApp Web (QR code)

Once the Gemini API key is set (via the setup UI or `.env`), `npm start` moves on to WhatsApp and
prints a QR code directly in your terminal:

1. On your phone, open **WhatsApp** → **Settings** → **Linked Devices** → **Link a Device**.
2. Scan the QR code shown in your terminal.
3. Once linked, you'll see `WhatsApp client is ready. Listening for messages...` in the logs.

The session is saved locally under `.wwebjs_auth/` (via `LocalAuth`), so you won't need to scan the QR
code again on subsequent runs unless you log out from your phone or delete that folder.

## Commands

| Command      | Who can send it                | Effect                                              |
| ------------ | ------------------------------- | ---------------------------------------------------- |
| `/pause`     | Anyone, in their own chat       | Disables auto-reply for that one chat                |
| `/resume`    | Anyone, in their own chat       | Re-enables auto-reply for that one chat               |
| `/pauseall`  | You (the account/session owner) | Disables auto-reply globally, across every chat       |
| `/resumeall` | You (the account/session owner) | Re-enables auto-reply globally                        |
| `/status`    | You (the account/session owner) | Logs the current global pause state to the console    |

Owner-only commands work by sending the command from your own phone/WhatsApp app (since the bot runs
as your linked device, those messages arrive as "sent by me" and are handled separately from replies).

## Configuration

See `.env.example` for the full list of tunable environment variables, including:

- `GEMINI_MODEL` — defaults to `gemini-flash-latest`; point it at a different Gemini model name if you
  want to trade off speed/cost against quality.
- `MAX_HISTORY_MESSAGES` — how many recent messages (user + model) are kept per contact for context.
- `RESPOND_TO_GROUPS` — off by default; set to `true` to let the bot reply inside group chats too.
- `DEBOUNCE_MS`, `MIN_TYPING_DELAY_MS`, `MAX_TYPING_DELAY_MS` — control the natural-feeling delay before
  a reply is sent.
- `MAX_CONCURRENT_CALLS`, `MAX_RETRIES`, `RETRY_BASE_DELAY_MS` — throttling/retry behavior for the
  Gemini API.
- `SYSTEM_PROMPT` — override the bot's persona entirely. The default persona ("Aria") is defined in
  `config.js` and is instructed to actually answer questions (math, facts, etc.) instead of giving
  generic greetings.
- `SETUP_UI_PORT` — port the local setup UI listens on (default `3000`), if that port is already taken
  on your machine.

## Notes and caveats

- `whatsapp-web.js` automates the WhatsApp Web interface; it is **not** an official WhatsApp API. Use it
  for personal/experimental purposes and be aware that automating WhatsApp can violate WhatsApp's Terms
  of Service and carries a (generally low but non-zero) risk of the linked number being restricted.
  Don't use this against numbers or accounts you don't own or have permission to automate.
  Consider the [WhatsApp Business Platform](https://developers.facebook.com/docs/whatsapp) for a
  production/official integration.
  - It uses Puppeteer/Chromium under the hood. On some Linux hosts you may need extra system libraries
  for headless Chrome; if `npm start` fails during browser launch, install your distro's Chromium
  dependencies (e.g. `apt install -y chromium` or the libraries it depends on).
- Conversation history and pause state are stored unencrypted in `data/state.json` (path configurable
  via `DATA_FILE`). Treat it like any other file containing chat content.
- The bot only replies to plain text messages (`msg.type === 'chat'`); media, stickers, etc. are
  ignored for now.
